# 📦 Руководство по переносу подхода к документации

Этот документ описывает, как перенести систему документации из Budget Assistant v2.0 в другой проект.

---

## 🎯 Что переносим

### 1. Система документации (README + docs/)
- **README.md** — пользовательский документ (30-60 секунд чтения)
- **docs/CODEBASE_ANALYSIS.md** — техническая карта кодовой базы для разработчиков
- **docs/TESTING_DOCS.md** — гайд по тестированию документации
- **Структура docs/** — организация документации по категориям

### 2. Вспомогательные файлы
- **AGENTS.md** — краткие guidelines для AI coding assistants
- **CLAUDE.md** — полная техническая документация для AI assistants (опционально)

### 3. Система управления промптами (опционально, для LLM-проектов)
- **prompts/agents/** — Jinja2-шаблоны промптов
- **prompts/loader.py** — загрузчик с динамическими переменными
- **prompts/agents/README.md** — документация prompt engineering техник
- **Не включено в основной промпт** — переноси отдельно если нужно

---

## 📂 Файлы для копирования

### Обязательные
```
README.md                          # Адаптировать под свой проект
docs/CODEBASE_ANALYSIS.md          # Адаптировать структуру
docs/TESTING_DOCS.md               # Создать по шаблону из промпта
AGENTS.md                          # Адаптировать команды
```

### Опциональные
```
CLAUDE.md                          # Если используете Claude Code
docs/TESTING.md                    # Если есть unit/integration тесты
docs/UX_UI_DESIGN.md              # Если есть UI/UX
prompts/                           # Только для LLM-проектов
├── agents/
│   ├── README.md                  # Техники prompt engineering
│   └── *.j2                       # Ваши промпты (создать новые)
└── loader.py                      # Копировать как есть
```

## 🚀 Промпт для Claude/AI Assistant

Используй этот промпт, чтобы настроить документацию в новом проекте:

```markdown
Мне нужно настроить структуру документации и систему управления промптами для моего проекта, основываясь на подходе из Budget Assistant v2.0.

## Контекст проекта
- **Название:** [название проекта]
- **Назначение:** [краткое описание, что делает проект]
- **Технологии:** [основной стек]
- **Использует AI/LLM:** [да/нет, если да — какие модели]

## Что нужно сделать

### 1. Создать README.md
Структура:
- 🤔 **Что это?** — 2-3 предложения
- 💡 **Зачем?** — 5-7 ключевых преимуществ (чекбоксы)
- 🧠 **Ключевые [AI/технические] решения** (если применимо)
- 🚀 **Как быстро запустить?** — 2 варианта (локально + облако/docker)
- 📱 **Как использовать?** — команды, примеры
- 📚 **Куда идти дальше?** — ссылки на документацию

**Требования:**
- Читается за 30-60 секунд
- Без лишних англицизмов (только технические термины)
- Для русскоязычных проектов — на русском
- Секция для портфолио (если нужно для работодателя)

### 2. Создать docs/CODEBASE_ANALYSIS.md
Структура:
- ⚡ **TL;DR** — запуск в 3 команды, основные файлы
- ⚙️ **Как это работает** — mermaid диаграмма + 5 шагов
- 🚀 **Первые шаги разработчика**:
  - Хочу запустить локально
  - Хочу понять [компонент A]
  - Хочу понять [компонент B]
  - Хочу добавить фичу
  - Хочу пофиксить баг
  - **Хочу изменить промпт и протестировать** (если используете LLM)
- 🗺 **Карта кодовой базы** — таблица файлов по слоям
- 🔬 **Углублённо** — детальные алгоритмы, паттерны

### 3. Создать систему промптов (если используете LLM)

**Структура:**
```
prompts/
├── agents/                    # или любое другое название
│   ├── README.md             # Документация prompt engineering
│   ├── [agent1].j2          # Промпты как Jinja2-шаблоны
│   └── [agent2].j2
└── loader.py                 # Загрузчик промптов
```

**prompts/loader.py:**
- Использует Jinja2 для рендеринга
- Функции-хелперы для каждого промпта
- Автоматическая подстановка переменных

**Пример переменных:**
- `{{ current_date }}` — текущая дата
- `{{ categories }}` — списки из конфига
- `{{ user_context }}` — динамический контекст

**prompts/agents/README.md:**
Документируй использованные техники:
- Role-based prompts
- Few-shot examples
- Constraint prompts
- Dynamic context injection
- Tool-use instructions
- Trigger lists

### 4. Создать AGENTS.md (для AI coding assistants)

Краткий справочник:
- 🚀 **Commands & Development** — команды запуска, тестов, линтеров
- 🎨 **Code Style Guidelines** — соглашения кода
- 🤖 **[Специфика проекта]** — архитектурные паттерны
- 📝 **Git & Documentation** — правила коммитов

**Цель:** AI assistant должен за 30 секунд понять как работать с проектом.

## Что адаптировать под мой проект

1. **README.md:**
   - Заменить название, описание, технологии
   - Убрать/добавить секции под свой стек
   - Адаптировать "Ключевые решения" под свою архитектуру

2. **docs/CODEBASE_ANALYSIS.md:**
   - Перерисовать mermaid диаграмму
   - Переписать "5 шагов обработки"
   - Адаптировать секции "Хочу..." под свои компоненты

3. **prompts/:**
   - Создать свои промпты (не копировать Budget Assistant)
   - Использовать loader.py как есть (универсальный)
   - Документировать свои prompt engineering техники

4. **AGENTS.md:**
   - Заменить команды запуска/тестов
   - Адаптировать code style guidelines
   - Добавить специфику своего проекта

## Начни с этого

1. Создай структуру папок
2. Скопируй prompts/loader.py без изменений
3. Создай README.md по шаблону выше
4. Создай docs/CODEBASE_ANALYSIS.md с TL;DR
5. Если используешь LLM — создай первый промпт в prompts/agents/
```

## 💡 Ключевые принципы

### Документация
1. **README за минуту** — пользователь должен понять проект за 30-60 секунд
2. **CODEBASE_ANALYSIS для разработчиков** — техническая карта без воды
3. **Без англицизмов** — только технические термины, остальное на родном языке
4. **Для портфолио** — секции о решённых вызовах, метриках, технологиях

### Промпты
1. **Jinja2 шаблоны** — индустриальный стандарт, не markdown
2. **Динамические переменные** — категории, даты, форматы инжектятся в runtime
3. **Документированные техники** — в prompts/agents/README.md
4. **Версионирование** — промпты в git, меняются как код

### AI Assistants
1. **AGENTS.md для быстрого старта** — все команды в одном месте
2. **CLAUDE.md для деталей** — полная техническая документация (опционально)
3. **Явные инструкции** — не полагаться на догадки AI
