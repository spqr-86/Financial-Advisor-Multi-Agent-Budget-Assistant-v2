# 🤖 AGENTS.md - Development Guidelines for Budget Assistant v2.0

This document provides essential instructions for agentic coding tools (like Claude Code, Cursor, or OpenCode) working on the Budget Assistant project.

## 🚀 Commands & Development

### Installation
- **Install all dependencies:** `poetry install`
- **Scaffold environment:** `cp .env.example .env`

### Testing (Pytest)
- **Run all tests:** `poetry run pytest`
- **Quick run (no coverage):** `poetry run pytest -q`
- **Run specific file:** `poetry run pytest tests/test_core/test_schemas.py`
- **Run single test:** `poetry run pytest tests/test_core/test_schemas.py::test_query_request_valid`
- **Run with coverage report:** `poetry run pytest --cov=src --cov-report=term-missing`
- **Minimum coverage requirement:** 50% (enforced in CI/CD)

### Quality Assurance
- **Lint code:** `poetry run ruff check src/`
- **Fix linting issues:** `poetry run ruff check src/ --fix`
- **Format code:** `poetry run ruff format src/`

### Running Locally (3 Terminals)
1. **MCP Service (8082):** `poetry run python -m src.mcp.app`
2. **API Gateway (8081):** `poetry run python -m src.api.app`
3. **Bot (Polling):** `poetry run python -m src.bot.run_polling`

## 🎨 Code Style Guidelines

### Python Conventions
- **Naming:** `snake_case` for variables/functions, `PascalCase` for classes, `UPPER_SNAKE_CASE` for constants.
- **Typing:** Use type hints for all function arguments and return types.
- **Async:** Use `async/await` for all IO-bound operations (HTTP calls, storage access, bot handlers).
- **Docstrings:** Use Google-style docstrings for modules and complex functions.
- **Formatting:** Adhere to Ruff defaults (88 character line limit).

### Service Architecture Patterns
- **API Gateway:** Uses FastAPI, Pydantic v2 models for validation, and proxies requests to MCP.
- **MCP Service:** Multi-agent system using `google-adk`. Business logic resides in agents and tools.
- **Telegram Bot:** Uses `aiogram 3.x`. Keyboards are in `src/bot/keyboards/`, formatters in `src/bot/formatters/`.

### Error Handling
- **Exceptions:** Use custom exceptions from `src.core.exceptions.py` (e.g., `ServiceUnavailableError`, `QuotaExceededError`).
- **Handlers:** FastAPI services must use `budget_exception_handler` for consistent error responses.
- **Bot Handlers:** Catch specific exceptions to provide user-friendly error messages instead of technical tracebacks.

### Imports
- **Absolute Imports:** Always use absolute imports starting with `src.`.
- **Order:** Standard library -> Third-party -> Local `src` modules (managed by Ruff).

## 🤖 AI Agent System (google-adk)
- **Agents:** Defined in `src/mcp/agents/adk_agents.py`.
- **Tools:** Defined in `src/mcp/agents/tools/`. Tools should interact with `StorageInterface`.
- **Prompts:** Jinja2 templates in `prompts/agents/*.j2`. Loaded via `prompts/loader.py` with dynamic variables.
- **Orchestrator:** The root agent routes intents to specialized agents (Registrar, Analyst).

## 📝 Git & Documentation
- **Commit Messages:** Format as `type: description` (e.g., `feat: add category detail formatter`). Do not add "Generated by AI" footers.
- **Documentation:** Keep `CLAUDE.md` and `docs/` updated. Create implementation plans in `docs/plans/` before major changes.

## 🧪 Testing Best Practices
- **Mocking:** Use `unittest.mock.AsyncMock` for async service-to-service calls.
- **Coverage:** Aim for 100% in `src/core/` and at least 50% overall.
- **Isolation:** Tests should not depend on live Telegram API or live Google Sheets. Use mocks or local storage simulations.
